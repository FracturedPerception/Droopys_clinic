# Droopy's_Clinic
## Возможности
### Система предназначена для учёта пациентов поликлиники, ведения электронных медицинских карт, организации записи на приём к врачам и управления расписанием. В системе отслеживаются:

- #### персональные данные пациентов (ФИО, дата рождения, полис ОМС, телефон, адрес)
- #### учётные записи (УЗ) пациентов, врачей и администраторов
- #### расписание приёмов врачей
- #### записи на приём (статусы: записан, завершён, отменён, неявка)
- #### электронные медицинские карты (жалобы, диагнозы, назначения, история болезни)
- #### изменения в системе (журнал изменений, возможность отката)
- #### жалобы пациентов на врачей


## Архитектура и способы реализации проекта
### Для реализации системы выбрана трёхуровневая (многослойная) архитектура — она удобна тем, что позволяет разрабатывать и тестировать уровни независимо, а также менять хранилище данных без переписывания бизнес-логики.
- #### Presentation Layer (слой интерфейса): Консольная программа. (Возможный переход к веб интерфейсу или десктоп приложению по мере разработки)
- #### Business Logic Layer (слой бизнес-логики): проверка корректности и уникальности данных пациента; контроль доступности времени врача при записи; управление статусами записей («записан», «завершён», «отменён», «неявка»); разграничение прав доступа между ролями; ведение журнала изменений с возможностью отката. Реализация: язык Python.
- #### Data Layer (слой данных): хранение информации о пациентах, врачах, записях на приём и медкартах. Реализация: реляционная база данных MySQL / PostgreSQL. Для учебного прототипа допустимо хранение в CSV/JSON.
